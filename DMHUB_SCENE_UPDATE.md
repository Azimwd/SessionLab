# Урон и участники сцены в DMHub

## Установка

1. Обновите backend и frontend из полного архива и перезапустите backend. Для этого обновления новых миграций нет; если ещё не установлено удаление кампаний, выполните `python manage.py migrate` для миграции 0016.
2. В моде комнаты DMHub замените Main целиком кодом `scripts/SessionLabRoom_Main.lua`.
3. В моде листа замените Main целиком кодом `scripts/SessionLabSheet_ASCII.lua`.
4. Перенесите свои значения URL и TOKEN в начало каждого файла. Нужен личный ключ пользователя от той же кампании, не ключ публичного моста чата. У игроков должны быть свои ключи.
5. Откройте панель «SessionLab · комната» или командой `/slroom`. Мод листа открывается командой `/slsheet`.

## Мастер: участники

Откройте «Участники» → «Добавить из листа». Выберите лист, число экземпляров NPC и защиты, затем подтвердите добавление. Разные экземпляры NPC имеют независимые ХП. Персонаж игрока добавляется один раз, его ХП связаны с исходным листом.
В настройках участника доступны имя, ХП, временные ХП, видимость, возможность выбора целью, сопротивления, иммунитеты и уязвимости. Нажатие на строку защиты переключает её значение. «Все типы» задаёт общую защиту; явно выбранный тип имеет приоритет.
Удаление участника из сцены требует второго нажатия. Лист-шаблон не удаляется.
На сайте тот же блок называется «Участники сессии» и находится в игровой комнате мастера.
Это состав текущей сцены для применения урона; порядок инициативы по-прежнему настраивается в своей вкладке. Изменение сцены не меняет автоматически трекер инициативы.

## Игрок: урон

После атаки или заклинания нажмите «Нанести урон» в последнем результате листа — откроется нужный бросок во вкладке «Урон» комнаты. Либо откройте «Урон» вручную и выберите свой результат.
Выберите одну цель для атаки или несколько для заклинания со спасброском/автоматического урона. Для атаки отдельной отметки попадания нет: при попадании нажмите «Нанести урон», при промахе закройте выбор целей. Для спасброска отметьте «Прошёл / Не прошёл» со слов мастера, затем примените урон.
Сервер применяет защиты, снимает временные ХП, затем обычные ХП. Одобрение мастера не требуется. Игрок не может менять величину сохранённого броска или защиты цели. Чужие броски, скрытые и запрещённые цели недоступны. Мастер видит все результаты своей кампании.
Здоровье и защиты целей в ответах игроку отсутствуют; в выборе целей показываются только имена. Урон применяется к той же сцене, что на сайте.

## Повтор запроса и ограничения

При обрыве связи кнопка «Повторить запрос» сохраняет первоначальные данные и ключ запроса. Один бросок атаки нельзя списать повторно; урон со спасброском нельзя повторно списать с той же цели. Сервер отклоняет действия после смены сессии и устаревшие настройки участника.
Вкладка показывает последние 100 событий действий текущей сессии и последние 100 применений урона. Повтор более старого результата всё равно проверяется на сервере.
Применение работает с сохранёнными результатами атак и заклинаний; свободные броски кубиков не являются источниками урона. Для смешанного урона и условных сопротивлений действуют ограничения базового механизма сцены. Отмены уже нанесённого урона нет; мастер может поправить ХП.
Проверены серверная логика и имитация интерфейсных API Lua. Проверка в запущенном клиенте DMHub пользователем остаётся необходимой: среда разработки не содержит самого клиента.

## API

- `GET /api/integrations/dmhub/scene/` — участники, доступные сохранённые результаты и история; `?view=player` скрывает мастерские данные.
- `POST /api/integrations/dmhub/scene/commands/` — `damage`, `add`, `update`; обязательны личный Bearer-ключ, Idempotency-Key и id активной `session`.

Логика применения урона и настройки целей общая с API сайта.

## Оформление комнаты

Развёрнутая комната имеет непрозрачный фон #101217, как лист персонажа. Персонажи за столом, участники сцены, строки инициативы и выбор целей разделены карточками с рамками и отступами. Текущий ход и выбранные цели выделены фиолетовым; активная вкладка и выбранный исход также подсвечиваются. Компактный трекер сохраняет прежний полупрозрачный фон. Обновление дизайна требует только замены Main мода комнаты; сервер для него менять не нужно.

## Лечение заклинаниями

Поддержано применение лечебных заклинаний на сайте и в DMHub. Типы результата `лечение`, `исцеление`, `healing` и `heal` означают восстановление ХП. «Лечащее слово» из каталога уже имеет нужный тип.
В редакторе действия добавлен выбор «Эффект»: урон либо восстановление ХП. Выбор лечения устанавливает автоматическое применение и тип «лечение». Для лечебного результата отображается «Вылечить», без запроса попадания и спасброска.
Восстановление ограничено максимальными ХП; временные ХП не меняются; сопротивления, иммунитет к урону и уязвимости не участвуют. Поднятие связанного персонажа с 0 ХП сбрасывает счётчики спасбросков от смерти. Особые ограничения заклинания (например, тип существа) по-прежнему оцениваются за столом.
Сохраняются авторство броска, права на цели и защита от повторного применения. Лечебный эффект нельзя выбрать произвольно при списании чужого или атакующего результата — сервер берёт тип и величину из сохранённого броска.
Для этого обновления нужно обновить backend, frontend и оба Lua-мода. Новых миграций нет. Обновление только Lua поверх старого сервера не добавит лечение.

## Несколько бросков в моде комнаты

В результате с несколькими частями теперь можно выбрать несколько бросков. Каждая строка переключается между [ ] и [X]; есть «Выбрать все» и «Снять выбор». Уже применённые атаки повторно не выбираются. Цель для выбранных атак указывается один раз; все они считаются попавшими. Промахнувшиеся броски исключите из выбора. Для спасбросков исход указывается отдельно для каждой выбранной части. Урон применяется одним атомарным запросом, защиты и округление учитываются отдельно. Повтор запроса использует прежний ключ и неизменный набор частей.
Замените Main мода комнаты файлом scripts/SessionLabRoom_Main.lua, сохранив URL и TOKEN. Мод листа менять не нужно. Сервер должен содержать ранее добавленную поддержку пакетного применения бросков (parts); если сайт ещё не обновлён до этой версии, обновите backend из полного архива. Для этой правки новых миграций нет.
