# Цели сцены: прямое применение урона игроком

## Обновление

Обновите backend и frontend из полного архива, сохранив свои .env, базу и media. Перезапустите backend и пересоберите frontend (`npm ci`, `npm run build`).

Если предыдущая версия целей сцены уже установлена, новых миграций и seed-команд нет. При первой установке целей сцены выполните в backend `python manage.py migrate` (lab.0015_scene_targets_damage).

Это обновление сайта. Lua-моды DMHub не меняются.

## Работа

Мастер добавляет участников в «Цели сцены», выбирая лист-шаблон и число экземпляров NPC. У каждой копии свои ХП, временные ХП, состояния и защиты. Шаблон не получает урон. У единственного экземпляра персонажа игрока здоровье и состояния связаны с его листом.

Сопротивления, иммунитеты и уязвимости задаёт мастер при добавлении или в настройках участника сцены. Игрок не может их менять через форму применения урона или API. Исходный лист-шаблон от настроек цели не меняется.

После своего броска атаки или заклинания игрок нажимает «Применить к цели» и выбирает участников. Для атаки отдельный выбор попадания не нужен; для спасброска отмечает «Прошёл» или «Не прошёл» отдельно у каждой цели, по объявленному за столом результату. Нажатие «Нанести урон» сразу списывает урон. Очереди подтверждения мастером и кнопки «Рассмотреть» больше нет.

Сначала сервер берёт сохранённый результат броска и учитывает попадание либо спасбросок, затем защиту цели, временные и обычные ХП. Сопротивление делит урон пополам с округлением вниз, иммунитет даёт ноль, уязвимость удваивает. Игрок не присылает произвольную сумму урона. Изменение режима атаки после броска не перебрасывает результат.

У атакующих заклинаний есть режим «Обычный / Преимущество / Помеха» до броска. Исход спасброска — отдельный выбор, независимый от режима атаки.

Для одной атаки выбирается одна цель. Для нескольких лучей применяется конкретная часть результата. Заклинание без броска атаки можно применить к нескольким целям. Все выбранные цели проверяются в одной транзакции: если одного исхода не хватает или цель недоступна, урон не применяется ни к одной.

## Старые запросы и исправление HTTP 500

Ожидающие запросы предыдущей версии не требуют рассмотрения: автор может заново выбрать цель в исходном результате и нажать «Нанести урон»; существующая запись будет использована. Старую неприменённую атаку можно переназначить другой цели. Уже применённый урон не дублируется.

Старый endpoint `/scene/damage/<id>/resolve/` сохранён для совместимости. Автор может завершить свой ожидающий запрос с исходом попадания/спасброска. Другие игроки не могут завершать чужие запросы. Устаревшие мастерские параметры урона/защиты не доступны игрокам.

Исправлена SQL-блокировка на этом endpoint: PostgreSQL блокирует только DamageApplication (`FOR UPDATE OF`), не nullable-связь CharacterSheet во внешнем соединении. Прежний запрос мог давать HTTP 500 в PostgreSQL, хотя проходил тесты SQLite.

## Приватность и ограничения

В списке целей для игрока нет ХП, максимальных или временных ХП, защит, состояний и ссылки на исходный лист. В общей ленте и ответе применения также нет ХП и подробностей защиты. Обычная комната и её журнал скрывают здоровье чужих листов; владелец по-прежнему видит собственное.

Режим рассчитан на доверенную группу: мастер объявляет попадание/исход спасброска, а игрок применяет урон только при попадании и отмечает в интерфейсе исход спасброска. Сервер проверяет автора сохранённого броска, кампанию, активную сессию, видимость/доступность целей и отсутствие повторного применения.

Учитывается один тип урона из способности. Смешанный и условный урон разрешается с мастером вручную; автоматического разбора текста правил нет. Механизм применяется к числовому урону атак/заклинаний, не к произвольным броскам кубиков; лечебные заклинания восстанавливают ХП. Отдельной отмены уже применённого урона нет; мастер может исправить ХП в настройках цели.

Лечение: результаты с типом «лечение», «исцеление», healing или heal теперь восстанавливают ХП выбранной цели до максимума. Временные ХП и защиты от урона не меняются. В редакторе действия доступен выбор эффекта. Подробнее см. DMHUB_SCENE_UPDATE.md, раздел «Лечение заклинаниями».

История урона и лечения на сайте ограничена по высоте (340 px, на низких экранах — до половины окна) и прокручивается отдельно. Сервер отдаёт страницы по 10 записей. Переходы «Назад», «Далее», «К последним» не загружают всю историю. API поддерживает page_size (1–50) и before (ID последней записи предыдущей страницы); старый формат ответа без этих параметров сохранён. Для установки обновите backend и пересоберите frontend. Миграций и обновления Lua для этой правки не требуется.

Несколько бросков: в результате с несколькими частями вместо выпадающего списка теперь флажки, «Выбрать все» и «Снять выбор». Цели выбираются один раз для выбранных частей. Если среди частей есть атака, выбирается одна общая цель. Исход спасброска задаётся отдельно для каждой части. Все выбранные атаки считаются попавшими; промахнувшиеся броски нужно исключить из выбора. Весь набор применяется одним запросом, атомарно; защиты и округление рассчитываются отдельно для каждого броска. Повторное применение проверяется по каждой части. API принимает `{source_event, parts:[{part_index, targets, outcomes}]}`; прежний формат одного броска сохранён. Для этой правки обновите backend и frontend, затем пересоберите frontend и перезапустите сервер. Новых миграций и изменений Lua нет.

Выбор «Попал / Промах» убран из сайта и комнаты DMHub. Применение урона означает попадание; клиенты отправляют hit=true автоматически. При промахе закройте выбор целей или снимите флажок с броска. Исход спасброска остаётся обязательным. Серверный контракт не изменён. Для этой правки пересоберите frontend и замените Main мода комнаты; backend и миграции менять не нужно.
