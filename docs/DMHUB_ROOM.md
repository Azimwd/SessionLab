# SessionLab · комната для DMHub

Отдельный третий мод. Он не заменяет мод листа или мост бросков. В моде нет журнала и произвольных бросков кубиков; страницы сайта `/room` и `/master` сохранены. При запуске инициативы сервер бросает инициативу выбранным участникам по тем же правилам, что на сайте.

## Установка

1. Обновите backend из архива, сохранив `.env`, базу и media. Нужны `lab/api/room.py`, новый `lab/api/dmhub_room.py` и `config/urls.py`. Перезапустите backend. Миграции, seed и пересборка frontend не нужны.
2. В DMHub создайте отдельный Lua-мод и вставьте целиком `scripts/SessionLabRoom_Main.lua` в его Main.lua. Исходник должен заканчиваться строкой `-- End.`. Используйте ASCII-сборку, а не читаемый UTF-8 source.
3. В `TOKEN` вставьте свой личный ключ из «Мой профиль → Мой лист в DMHub» выбранной кампании. Это тот же личный ключ, что для листа; общий ключ моста бросков не подходит. У каждого участника свой ключ. Личный ключ мастера нельзя раздавать игрокам или публиковать вместе с модом.
4. Откройте игровой стол DMHub. Добавьте панель «SessionLab · комната» и нажмите «Открыть комнату». Альтернативная команда: `/slroom`. Закрытие окна останавливает опрос; повторное открытие подключает заново.

## Что есть в окне

- «За столом»: реальные папки кампании, раскрытие/сворачивание папок, имя, класс, уровень, хиты, временные хиты, КД, скорость, инициатива, характеристики и состояния.
- Игрок видит только открытые мастером папки и карточки. Скрытые карточки не передаются API игроку.
- Мастер переключает общую видимость стола, видимость каждой папки и каждой карточки. Эти настройки общие с сайтом; скрытие папки не меняет индивидуальные флаги карточек.
- «Вид игрока» позволяет мастеру проверить публичное представление. Кнопки управления в этом режиме убраны. Обратное переключение — «Режим мастера».
- Инициатива: выбор листов по папкам, несколько экземпляров NPC (0–20 последовательными нажатиями), временный участник с именем, бонусом и количеством, запуск с серверными бросками.
- Список инициативы сортируется сервером по значению инициативы, затем Ловкости и стабильному ID. Пауза, продолжение, следующий ход, счётчик раундов, сброс с повторным подтверждением.
- Во время паузы можно изменить имя/инициативу, скрыть участника или удалить его. Изменение состава через новый массовый запуск требует сброса предыдущего боя.
- Скрытый участник не раскрывается игрокам; вместо его имени в текущем ходе показывается «Скрытый участник».
- «Свернуть» превращает окно в трекер шириной 400px: текущий участник, раунд, бой/пауза, следующий ход у мастера, статус подключения. «Развернуть» возвращает комнату. Оба вида перетаскиваются и сохраняют положение при переключении.

## Окно и синхронизация

Окно не использует `gui.ShowModal`, не создаёт полноэкранную подложку и не затемняет экран. Оно добавляется в слой `GameHud.instance.dialogWorldPanel`, имеет полупрозрачную поверхность и `blocksGameInteraction=false` у информационных контейнеров. Кнопки и поля остаются интерактивными. Поэтому информационные области рассчитаны на пропуск кликов к карте, а элементы управления забирают только свои клики. Реальное поведение слоёв, перетаскивания и прозрачности необходимо проверить в версии клиента пользователя; сам DMHub в среде разработки не запускался.

Опрос раз в 5 секунд, а не WebSocket. Изменения появляются без ручного обновления страницы с задержкой до интервала опроса и сети. Пустой опрос и чужие броски в чате не перестраивают содержимое комнаты. Форма подготовки не пересоздаётся при опросе, значения полей сохраняются.

Сетевой тайм-аут не доказывает, что действие не выполнилось. «Повторить запрос» использует прежний Idempotency-Key. После 409/конфликта нажмите «Проверить состояние» в полном окне и повторите нужное действие по свежей версии. Команды инициативы привязаны к ID активной сессии и версии трекера. Права мастера проверяются сервером при каждой записи, внутри транзакции с блокировкой кампании. Устаревшие ответы после закрытия/перезагрузки мода игнорируются.

## API

- `GET /api/integrations/dmhub/room/` — комната по личному Bearer-ключу.
- `GET /api/integrations/dmhub/room/?view=player` — публичное представление для проверки мастером.
- `POST /api/integrations/dmhub/room/commands/` — личный Bearer-ключ + Idempotency-Key. `command=visibility` использует `scope=table|folder|character`, `visible` и нужный ID. `command=initiative` использует `session`, `version`, `action` и параметры существующей инициативы.
- JSON-ответы и ошибки соответствуют общей envelope-схеме; ответы не кэшируются. OpenAPI доступен через `/api/docs/`.

Генерация мод-файла: `python scripts/build_dmhub_room.py`.

## Проверка

63 backend-теста комнаты, личных ключей, редактора и бросков прошли. Новые тесты проверяют права, фильтрацию скрытых папок/листов, вид игрока, отдельную кампанию, отзыв ключа, однократный запуск, версии, раунды и скрытый ход. Дополнительно повторно проверены три новых теста после добавления проверки ID сессии.

Lua-тест с имитацией нативного GUI проверяет немодальное открытие, прозрачность, границы компонентов, подготовку участников, количество NPC, ввод нескольких символов, повтор того же запроса, переключение ролей, компактный вид и очистку ссылок при закрытии. Тесты не заменяют проверку на реальном клиенте DMHub.


## Обновление оформления

Окно комнаты приведено к палитре остальных модов: фон #101217, поверхности #232833, рамка #303642, фиолетовый акцент #695CF5. Основное окно имеет радиус 12, кнопки и поля — 6. Сохранены немодальный режим, перетаскивание и лёгкая прозрачность. В компактном режиме «Развернуть», «Следующий ход», «Закрыть» стоят в одной строке общей шириной 376px с одинаковыми промежутками. У игроков без прав управления отображаются две равномерные кнопки. В полном режиме действия также выровнены в одну строку. Проверка Lua подтверждает размеры и общий контейнер кнопок, а также остальные сценарии комнаты. Требуется только замена Main.lua мода комнаты с сохранением TOKEN; backend и frontend менять не нужно.
